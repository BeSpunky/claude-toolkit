# R8 — adversarial review: platform firewall, house-app lint, Analog spec tsconfig, a11y shell

Scope: `nx-tools/src/platform/*`, `generators/platform`, tagging at creation, migrations `close-the-platform-firewall`,
`lint-house-apps`, `state-analog-spec-tsconfig`, `add-design-system-a11y`, `_utils/lint-inference.ts`,
`adapters/angular/{app-shell,analog-tsconfig}.ts`, `_a11y.scss.tpl`. Paths are relative to `plugins/house/engine/nx-tools/src/`.

Evidence: probe `scratchpad/r8/probe.mjs` ran `classifyWorkspace` on a fixture built from the compiled payload. Output:

```
a   server  imports firebase-admin/app            (`import type` only; lint flags it too, so consistent)
b   server  imports firebase-admin                (the "import" is a // COMMENT)
c   server  imports firebase-admin/app            (only in index.spec.ts)
d   shared  []                                    (import(`firebase-admin`): template literal, missed; lint also misses it)
e   shared  []                                    (imports node:fs; there is no server evidence for it)
f   web     imports firebase                      (the "import" is inside a STRING literal)
web null    angular stack + firebase-admin/auth in src/server.ts  (SSR; left untagged)
```

Nx 23 sources read: @nx/eslint-plugin 23.3 `enforce-module-boundaries.js` (AST visitors, no type-only exemption),
@nx/eslint 23.1 `plugins/plugin.js` (every project root is grouped under its nearest eslint config dir) and
`lint-project.js`.

## Findings (ranked)

### R8-1 · HIGH · confidence high · platform/classify.ts:235, 354
**The classifier's import regex also matches comments and string literals, but the firewall reads the AST.**
`IMPORT` runs over the raw file text. Probe results: `b` (a comment that says "never import from 'firebase-admin'")
was classified **server**, and `f` (a string literal) was classified **web**. ESLint flags neither. Failure: during the
migration, a pure lib is tagged `platform:server`, and every web app importing it then fails
`onlyDependOnLibsWithTags`, even though nothing leaks. If the same file also gets the opposite stray evidence, the lib
reads as "mixed" and stays untagged. The classifier and the firewall disagree about the same file, which is exactly
what `externals.ts`'s header says must never happen.
**Fix:** use `ts.preProcessFile(text, true, true).importedFiles` (TypeScript is already loaded through
`loadTypeScript` for the firewall), or walk the AST for import/export/`import()`/`require` with a literal argument.
That is the same set of nodes Nx visits.

### R8-2 · HIGH · confidence high · migrations/0.50.0/close-the-platform-firewall.ts:23 (claim), platform/index.ts:34
**A mixed project that nothing imports (every app) leaves the firewall entirely.** The header says *"a mixed
project stays untagged and lint names it"*. Lint only names it when a tagged project imports it. An untagged project
matches no `platform:` sourceTag, so its own imports are never checked. Probe: an untagged Angular app whose SSR
`server.ts` imports `firebase-admin` comes back `null`, is skipped, and from then on imports anything. So "fail
closed" opens for exactly the project that holds the leak.
**Fix:** for an application, the stack's platform is authoritative. Tag the app with it (web), and let lint report
the offending import at the line where it happens. Reserve "unresolved" for libraries. At minimum, report every
untagged leaf as **unchecked** rather than "lint names it".

### R8-3 · MEDIUM · confidence high · platform/externals.ts:82-83, classify.ts:191
**"No evidence → shared" fails open, and the evidence table only knows about Firebase and Angular.** Probe `e`: a lib
that imports `node:fs` is classified **shared**, so web apps may import it and lint stays green. These are invisible
to the table: Node builtins (`node:*`, `fs`, `child_process`…), `@google-cloud/*`, `firebase-functions-test`,
`express`, and on the web side `@firebase/*` (the modular SDK's real packages) and `rxfire`. Shared is the lattice's
bottom, so every gap in the table resolves toward the permissive tag, and the tag is then **written into project
files**.
**Fix:** add Node builtins (from `module.builtinModules` plus `node:*`) and `@google-cloud/*` as server evidence, and
`@firebase/*` as web evidence (see dispute D1 for SSR first). Report evidence-free libraries as "shared by default"
in a separate list, not as an inference.

### R8-4 · MEDIUM · confidence high · platform/firewall.ts:162-163 vs index.ts/classify
**The migration keeps the project's own ban additions, but the classifier ignores them.** The new `platform:shared`
constraint bans the union of the bans the config *declares*. The classifier uses only the computed table. If a
project added (for example) `'express'` to `platform:web`'s bans, a lib importing express is classified shared, and
the next lint fails the lib on its own import. These are the "two copies" `externals.ts:65-67` exists to prevent.
**Fix:** classify with table ∪ the declared lists that `upgradePlatformFirewall` has already parsed (return them
from it).

### R8-5 · MEDIUM · confidence high · classify.ts:233 (SOURCE_FILE) + the firewall's `files` scope
**Test files are platform evidence and get linted by the firewall.** Probe `c`: a lib whose only `firebase-admin`
use is in `*.spec.ts` (seeding the emulator through admin, which is common) is classified server. Rules tests in
functions that use the client `firebase` SDK make the project mixed. Either case puts real projects into the
untagged state, and their importers fail.
**Fix:** exclude `*.{spec,test}.*`, `test-setup.*` and `e2e/` from evidence, and give test files a firewall exemption
(a flat-config block for `**/*.{spec,test}.ts` without the platform bans). Otherwise say plainly that tests are held
to the platform.

### R8-6 · MEDIUM · confidence medium-high · _utils/lint-inference.ts:63-68; lint-house-apps.ts
**Registering `@nx/eslint/plugin` adds a `lint` target to every project under the root config, and nothing says so.**
@nx/eslint 23's `groupProjectRootsByEslintRoots` assigns every project root to its nearest eslint config, and the
root config is that config for all of them. After this rung, the design system, the vendored navigation kernel
(which is written "byte-for-byte, never formatted"), e2e projects and tooling projects with `.mjs` files all gain
`lint`. `run-many -t lint` and CI start failing on code that was never linted. The rung's log names only the apps.
**Fix:** before registering, list the projects that will newly gain `lint` and report them. Or register with
`include` limited to the projects the house means to lint.

### R8-7 · MEDIUM · confidence high · design-system wiring vs adapters/angular/index.ts:132
**The skip-link markup is unconditional, but its style is not.** `seedAppShell` runs for every Angular app.
`.skip-link { @include ds.skip-link(); }` is seeded only by `design-system-styles`, on first wiring. An Angular app
without the design-system layer (`add-layer angular`, or the `app` generator in a workspace without a design system)
ships a **permanently visible, unstyled** "Skip to main content" link at the top of every page.
**Fix:** seed the markup from the same per-app step that seeds its look (design-system-styles). Or, with no design
system, have the stack seed a self-contained visually-hidden-until-focus rule. Add a generator case for an app
without a design system.

### R8-8 · LOW-MED · confidence high · _utils/lint-inference.ts:48-55, 78-89
**`inferredLintTarget` ignores a plugin entry's `include`/`exclude` and any later entries.** If the workspace scopes
`@nx/eslint/plugin` (`include: ['libs/**']`), `convertBareLint` still deletes an app's explicit target. The plugin
never infers one for that app, so the app silently has **no lint** and the firewall is off for it.
**Fix:** match the entry's include/exclude globs against the project root (as Nx does). If any entry excludes it,
keep or convert to the explicit target.

### R8-9 · LOW · confidence high · migrations/0.50.0/lint-house-apps.ts:142, 190-195
**The outcome depends on order across apps.** The first unlinted house app runs add-linting, and its
`convertBareLint` registers the plugin. For every app after that, `isLinted` returns true, because the plugin is now
present and the root `eslint.config.mjs` exists. So only the first app gets the Angular rules and its own
`eslint.config.mjs`.
**Fix:** take the "already linted" snapshot before the loop. Also include `eslint.config.mts/.cts` in
`ESLINT_CONFIGS`.

### R8-10 · LOW · confidence medium · adapters/angular/app-shell.ts:22,30; _a11y.scss.tpl
**Focus lands on `<main tabindex="-1">` with no style for that state.** After the skip link is activated by
keyboard, `main.focus()` matches `:focus-visible`, so the UA draws its outline around the whole content area. Also,
`tabindex=-1` makes any mouse click inside `<main>` move focus to `<main>`. Neither is addressed by the DS or the
seed.
**Fix:** have the DS ship the landmark half, for example `ds.skip-target()` → `&:focus { outline: none; }` (or
`scroll-margin` from tokens), seeded beside `.skip-link`.

### R8-11 · LOW · confidence high · _a11y.scss.tpl:184
**The z-index claim is false.** `z-index: fn.z('modal')` ties with modals; it is not "above everything the page
stacks". A skip link focused while a modal is open (or one that comes later in DOM order) can be covered.
**Fix:** add a named top layer token (`z-skip-link` or `z-top`) to `_tokens.scss` instead of borrowing `modal`.

### R8-12 · LOW · confidence medium · migrations/0.50.0/add-design-system-a11y.ts:59-64, 80
**The migration forwards a file it did not write.** If the DS already has its own `_utils/_a11y.scss` (a common name)
without these mixins, the seed is skipped (`exists`). `clashingMixins` explicitly ignores that same path, and the
rung still forwards `show visually-hidden, skip-link` from the project's own file. Then `ds.skip-link()` is
undefined, and the `.skip-link` rule seeded on an app's first wiring breaks that app's SCSS build.
**Fix:** if the file exists and is not byte-equal to the template, report it and do not forward.

### R8-13 · LOW · confidence high · _utils/lint-inference.ts:92-99
**A `targetDefaults["@nx/eslint:lint"]` is deleted without a report.** If it carried the project's own options
(`maxWarnings`, `quiet`), those options no longer apply to the inferred target, which takes `targetDefaults.lint`.
Removing it is defensible, because nothing reads it any more. Losing the options silently is not.
**Fix:** when the entry has keys beyond inputs/cache, report what was dropped and where it now belongs.

### Checked, no finding
- **E3 type-checking:** the vitest config carries no `build`, and @nx/vite infers no build from it. The lib's build
  (ng-packagr / `tsconfig.lib.json`) and the `typecheck` target never read it. Naming `tsconfig.spec.json` changes only
  which path Analog resolves on a non-test load. No wrong type-checking. The migration reports configs that build
  instead of guessing.
- **Firewall AST upgrade:** constraints are located through the TS AST. The legacy comment is matched exactly, and
  constraints that already have `onlyDependOnLibsWithTags` are left alone.
- **Double lint:** the explicit target is only deleted when the inferred name is `lint`, so the two merge into one.
  When the inferred name differs, both targets remain (bare executor plus inferred). That is documented, but it is
  still double linting under a renamed plugin target.
- **Type-only imports:** Nx 23.3 checks them (no `importKind` exemption), so the classifier agrees with lint here.

## Design disputes

- **D1 · `platform:web` = "browser / SSR" conflates two runtimes.** SSR code (`server.ts`, Analog `src/server/**`) is
  server code: verifying tokens with `firebase-admin` there is legitimate and safe. The model forces those apps to be
  "mixed" (R8-2) and blocks fixing R8-3 for Node builtins, because SSR needs them. Model the SSR entry as its own
  sub-project or file scope, rather than widening `web`.
- **D2 · Being built by the Angular stack counts as web evidence on its own.** A model or contract library built with
  ng-packagr but importing nothing from Angular becomes web, and functions can no longer import it. Stack evidence
  should decide for applications. Imports should decide for libraries.
- **D3 · Tooling projects get a platform.** The classifier tags shared-browser, worktree-domains and similar tooling
  projects `platform:shared`. Their Node scripts are neither isomorphic nor imported. The header's own reason for
  excluding the root shell ("a tag is read about a project it lints or that something imports") applies to them too.
- **D4 · A regex classifier beside an AST enforcer.** Two parsers of the same imports will disagree (R8-1). There
  should be one import reader, AST-based, shared by the classifier, the `platform` generator and the migration.
- **D5 · The fail-closed rule rests on every future project being tagged.** Any `nx g @nx/js:lib` the user runs is
  untagged, and its first web importer fails with Nx's fixed message. The guidance comment helps. A cheaper fix
  belongs in the generators: `nx.json` `generators` defaults for `@nx/js:library` / `@nx/angular:library` `tags`, or a
  `platform` sync generator that tags new projects.
- **D6 · E3 rewrites configs the house did not write.** It edits every library's vitest config, including ones made
  with @nx/angular directly, to work around an upstream @nx/vitest omission. The house now owns that workaround
  forever, in files it doesn't own. Scoping it to house-created libraries, and linking the upstream issue, would bound
  that cost.
