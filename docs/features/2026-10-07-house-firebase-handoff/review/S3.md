## Design disputes

- **The identity layer has grown into a distributed lock manager.** It has a lock, takeover, boot id, PID namespace,
  heartbeat and prune, and S3-1, S3-7 and S3-8 are all races inside it. `flock(2)` on a file in the main tree's
  `.bespunky/run/` (Node: hold an fd through a tiny `flock` child, or use `proper-lockfile`-style O_EXCL plus a nonce)
  is released by the kernel on crash. That removes takeover entirely. Two containers sharing one mount are rare
  enough to refuse rather than model.
- **"Claude must use tools/dev/dev serve" belongs in code, not prose** (S3-9).
- **The emulator project id must come from evaluating environment.ts, not regex-reading it** (S3-2/3). The browser
  and the suite must share one function. Today the two are kept "in step" by comment.
- **push-secrets changing semantics is a one-way change to production data without a migration or report** (S3-4).
  This needs the backwards-compatibility question put to the user, and a refusal on any divergence.
- **e2e via a continuous dev-stack on an auto offset has no address contract** (S3-5). Either pin dev-stack to a
  declared offset per tree, or make the URL discoverable.

## Appendix A — serve and stack identity (detail)

# Adversarial review A — stack identity / claim / keeper / dev-stack (feat/house-firebase-handoff)

Paths relative to `plugins/house/engine/nx-tools/src/generators/` unless stated. Scratch harnesses: `scratchpad/s3/a/`.

## A1 — HIGH (run) — claim lock takeover is not mutually exclusive
`dev/files/lib/stacks.mjs.tpl:378-398`. Two contenders read the same dead `owner.json`; A renames the stale lock aside,
removes it, `mkdir`s a NEW lock and enters; B (whose stale verdict was about the OLD owner) then `renameSync(lock)` —
which is now A's live lock — and enters too. A's `finally rmSync(lock)` then deletes B's (or a third party's) lock,
cascading. The header comment ("atomically, by rename, so two claimers can never both take it over") is false.
Repro: `s3/a/round.sh` — a stale lock owned by dead pid 999999, 24 contenders released at one instant, a `wx` marker
inside the critical section (via the injected `probe`). 2/20 rounds: `OVERLAP: 18 3 15 24 19 23 20 9` and
`OVERLAP: 4 20 14 16 19 8 23 24 11`. Control (no stale lock, `round0.sh`): 0/20.
Consequence: two claims decide on the same block; same key is caught by `open wx`, but different apps (a serve + a
direct `firebase` run, or two apps) both write records on overlapping ports — the exact R3-1 bug. How a holder dies
holding it: SIGKILL/OOM, or a Ctrl+C during the claim (no SIGINT handler is installed until `runStack`, so node exits
without the `finally`).
Fix: never take over by renaming the shared name. Either (a) take over by renaming the stale dir only if its
`owner.json` still names the dead owner after the rename (rename to a private name, re-read owner from the renamed dir,
and if it is not the dead owner, rename it back / treat as lost race) — still racy; better (b) use an fd lock that the
kernel drops on death: `open(lockfile)` + `flock` is not in Node built-ins, but an `fs.openSync(path,'wx')` lock file
whose content is a nonce, with takeover by `link()`-to-unique-name + compare nonce, or (c) simplest: a lock per claim
attempt via `mkdir` of `claim.lock` and staleness resolved by `rmdir` only when the dir's inode equals the inode
observed when the owner was read (stat before read, rename to private, stat the private name, compare `ino`; mismatch
→ rename back is impossible, so instead make the rename target the inode-tagged name `claim.lock.<ino>` and only the
contender that observed that ino proceeds). Also make `finally` remove the lock only if it is still ours (compare the
owner/nonce first).

## A2 — HIGH (read) — `dev-stack` gives an e2e target no way to find the stack it started
`_utils/dev-server.ts:11-13,79-81`, `executors/serve/executor.ts:115-116`, HOUSE.md.tpl:168. `dev-stack` inherits
`portOffset: auto`. In any worktree `auto` never offers 0 (`lib/ports.mjs.tpl:95`), and in the main tree it moves off 0
whenever the developer's `nx serve`/`tools/dev/dev serve` holds it. Nothing passes the chosen offset/URL to the
dependent (no env, no file the e2e is told to read; `grep BASE_URL|baseURL|DEV_URL` → nothing). A conventional e2e
with `baseURL: http://localhost:4200` therefore: in a worktree, tests main's server (wrong code) or nothing; in main
beside the developer's serve, tests the developer's stack and writes into the developer's emulator world (which that
suite then exports to `.emulator-data`). FA's D check ("e2e via dev-stack, exit 0") ran with no concurrent serve, so
it could not see this. Also (suspected) Nx starts the dependent of a continuous task without a readiness gate.
Fix: publish the stack's URL/ports where a dependent can resolve them deterministically (e.g. `tools/dev/dev url <app>
[--worktree]` reading the record of this tree's live stack of that app, or a per-tree `.bespunky/run/<app>.current`
pointer written at claim), document it in HOUSE.md next to "depend on dev-stack", and have `dev-stack` print+wait for
readiness; or pin e2e to a declared offset. At minimum the doc must say the e2e must not hard-code the base port.

## A3 — MEDIUM (run) — stopping a seed-build stack orphans its emulator suite and drops its handle
`firebase-emulators/seed-build-seeds.sh.tpl:29-50` + `dev.mjs.tpl:621-633`. A `seed-build@N` record has `pid=$$`
(the bash script), `processes: []`, no keeper. `tools/dev/dev stop seed-build --offset=N` sends SIGTERM to the
script; bash has no TERM trap, dies at once (EXIT trap runs → `release` drops the record), and the foreground
`firebase emulators:exec` + JVMs keep running on the shifted block, still writing `tools/emulator-seeds/<seed>`.
Repro of the mechanism (`s3/a/seedlike.sh`, same `set -euo pipefail` + EXIT trap + foreground child): after SIGTERM
"bash alive: n; child alive: y; EXIT-trap-ran". stopOne then reports "still listening … not this stack's process any
more" for ports the stack itself left. Fix: register `firebase` as a recorded process of the stack (or run it under
the same keeper/detached-work contract), and trap TERM/INT/HUP in the script to stop the child and wait.

## A4 — MEDIUM (run) — sibling-container / host records are pruned while live, destroying their state dir
`dev/files/lib/stacks.mjs.tpl:100-116,307-316,339-341`.
- A record claimed on a non-Linux host sharing the bind-mounted repo (`machine: host:<name>`) is `dead` to every
  container reader at once (boot-id mismatch) — and vice versa — and `dropStack` deletes the live stack's record AND
  `stackDir` (its `detached/emulators.json`, stop file). Repro: a `host:macbook.local` record + a same-kernel record
  with mtime −70 s → `readStacks` returned `[]` and removed both files and the state dir.
- Same kernel, other namespace: liveness = mtime < 60 s. A stopped claimer (Ctrl+Z on a plain web serve — the keeper
  only exists for Firebase stacks) or a resumed laptop (VM monotonic timers fire up to 15 s after the wall clock has
  jumped) is pruned by the first `ps`/claim in the other container; the block is then claimed again on top of it
  (shared `.emulator-data-<offset>` for a Firebase stack → two suites exporting into one dir).
- After pruning, the victim's keeper's `entry_write` (node rename into the deleted `detached/`) fails; under
  `set -euo pipefail` inside the `if` body that exits the keeper (suspected) → firebase-tools runs unsupervised, the
  one-stop/export guarantee is gone.
Fix: never `rmSync` a foreign record's state dir on a timer verdict — mark it `stale-foreign`, refuse its block for
`auto`, and only delete when the reader can prove death (same table) or a human says `--prune-foreign`; treat
unknown/`host:` machines as `foreign`, not `dead`; make the keeper tolerate a missing `detached/` (mkdir -p before
each write, `|| true`).

## A5 — MEDIUM (read) — prune outside the lock can delete a freshly claimed stack (TOCTOU)
`stacks.mjs.tpl:319-347` with `dropStack:214-218`. `readStacks` is called without the lock by `ps`, `stop`, and the
keeper's `release_stack` (`emulators.sh.tpl:396-402`). It reads record R(old), judges it dead, then `dropStack(tree,
key)` deletes by PATH. If, between the read and the rm, a claim (inside the lock) pruned the same dead record and wrote
a new one of the same key (the Ctrl+C-and-restart path FA designed for: the claimer waits for the old keeper's
`exited` entry, which the keeper writes just BEFORE `release_stack`), the new live stack loses its record, its state
dir, and its TMPDIR (same deterministic `/tmp/bespunky-<hash>` — the running suite's hub json and function sockets).
Fix: prune only under the claim lock, or re-read the file and compare (`startedAt`/`pid`/inode) immediately before
removing; give the TMPDIR a per-claim component (e.g. hash includes `startedAt`) so a stale prune cannot hit a new run.

## A6 — MEDIUM (read) — agent rule contradicts the engine on the main tree; `nx serve` misuse only documented
HOUSE.rules.md.tpl:111 says Claude MUST never take the project's default/forwarded ports, and to serve with
`tools/dev/dev serve <app>`; local-server-isolation SKILL.md:38 says the same with no `--port-offset`. But `auto`
in the main tree prefers offset 0 (`ports.mjs.tpl:95`, `dev.mjs.tpl:393`), so an agent in the main checkout takes
4200/8080/9099 whenever the developer's server happens to be down — then the developer's next serve is pushed onto an
unforwarded block (OAuth origin broken). Fix: when the owner is an agent (`CLAUDE_CODE_SESSION_ID`/`DEV_OWNER` set),
`auto` must skip offset 0, or the docs must say `--port-offset` ≠ 0 explicitly.
Item 6: nothing enforces "don't `nx serve` as an agent": the executor has no agent check; a foreground `nx serve web`
in a Bash call prints nothing (Nx 23.3 summary) and blocks until the tool timeout kills it. Fix: in the executor, if
an agent is detected (`CLAUDECODE`/`CLAUDE_CODE_SESSION_ID`) and output style is summary, print the handle on stderr
via a path Nx shows, or refuse with "use tools/dev/dev serve".

## A7 — LOW (read) — `--abandon` / deadline: "DATA_DIR keeps what it held before" is not guaranteed; leak in repo root

## A10 — LOW (read) — shared-/tmp TMPDIR not ownership-checked
`stacks.mjs.tpl:49-57,499-500`. Path is predictable (sha256 of a known path + key). `rmSync` then
`mkdirSync({recursive:true, mode:0o700})`: recursive mkdir silently accepts a dir another user created in the window,
and an attacker-owned pre-existing dir makes `rmSync` throw EPERM after the record was already written (`wx`), failing
the claim. Only matters on a multi-user host (devcontainers have a private /tmp). Fix: `mkdirSync` non-recursive,
then `lstat` and verify uid + mode; on EEXIST fail with the owner named. TMPDIR also leaks whenever the record is
removed by anything but `dropStack` (worktree removed, `git clean -xfd`).

## B-1 (major, RUN) A comment inside EMULATE moves the suite onto the REAL project id; browser stays offline
`emulator-project.mjs.tpl:53-54`. The EMULATE body is `[^}]*` and every `(\w+)\s*:\s*(true|false)` in it is taken,
comments included, last wins. Rendered environment.ts with `projectId: 'acme-prod'` and either
`auth: true, // flip: auth: false to use real Auth` (a.ts) or a commented-out alternative line `// auth: false,`
(d.ts) resolves `EMU_MODE='real' EMU_REAL_SERVICES='auth'`. At runtime EMULATE.auth is `true`, so
`firebase.config.ts` `emulatorProjectId()` returns `demo-acme-prod`. Two consequences:
- The suite runs `--project=acme-prod` with the developer's login/ADC while every service is emulated.
  This is the exact state HOUSE.md ("real id **only** when environment.ts commits a service") and HOUSE.rules.md
  ("never set a service to false … without the user") say cannot happen silently.
- The browser and the suite split ids. Callables go to `/demo-acme-prod/…` on a suite serving `/acme-prod/…`.
  Auth accounts and seeds sit under the other project.

The template's own comment style (l.16, `auth: false` in a comment) invites this pattern.
**Fix:** stop regex-reading TypeScript. Node ≥22.18 strips types natively, and environment.ts imports only
`import type`, so `await import(envFile)` and read `environment.emulators.*.default` and `environment.firebase.projectId`.
That gives the same values the browser computes. Failing that, strip comments before matching, and refuse
(exit 2) on any ambiguity instead of guessing.

## B-2 (major, RUN) The converse: real intent read as offline, so the browser and suite split again
Same function. `const EMULATE: Record<string, boolean> = {` (b.ts) does not match `const\s+EMULATE\s*=`, so all
four services are `unread` and the suite goes offline. An app-specific top-level `auth: { providers: [...] }`
placed before `emulators` (c.ts; the interface invites "app-specific top-level fields") is taken as the auth
entry, so auth is unread and the suite goes offline. In both cases the browser has `auth.default === false`,
uses the real id, and talks to emulators running `demo-…`. The banner says "taken as emulated", which is
false for the browser. `field(source,'projectId')` has the same first-match-anywhere flaw: a `google: { projectId }`
block earlier in the file wins. **Fix:** same as B-1. At minimum, treat any `unread` as exit 2, not as emulated.

## B-3 (major, RUN) push-secrets now silently truncates production values at an unquoted `#`
`emulator-secrets.cjs.tpl:508-541`, `push-secrets.sh.tpl:641-650`. `.secret.local`: `DB_PASS=p@ss#w0rd` →
`push-entries` emits `DB_PASS|p@ss`, exit 0. The old script pushed the raw text. Every existing project
re-pushing an unquoted value containing `#` now overwrites the production secret with a prefix, without a
warning. The same happens for an unterminated quote: `A="abc` pushes `"abc`. A non-dry run prints nothing about it.
`.secret.local` is read by nothing but this script now; the emulator reads the bundle's file. So dotenv
semantics are a choice here, and its sharpest edge is unguarded. push-secrets.test.sh tests `#` only inside
quotes. **Fix:** compare the parsed value against `readRaw` for each key. When the difference is anything but
surrounding quotes, whitespace or a whitespace-preceded comment (an unquoted `#` with no space before it, a stray
or unbalanced quote), refuse the whole push and name the key. Add that case to the test.

## B-4 (medium, RUN/READ) The tripwire does not check where the emulator actually dials Secret Manager
`tools/test-firebase-tools/run.mjs:104-107,185-188`. Part 2 calls the getter `api.secretManagerOrigin()`, but
`gcp/secretManager.js:41` captures the origin once into a module-level `client` at load. An upstream change that

untested. `place()`'s launch check (l.446-461) has the same blind spot. A real dial test is cheap and was run here

`require('firebase-tools/lib/gcp/secretManager').accessSecretVersion('demo-x','S','latest')`. The listener receives
`GET /v1/projects/demo-x/secrets/S/versions/latest:access`. **Fix:** make that the tripwire's part 2 (assert that the
listener got the request), and use the same probe in `place()` instead of the getter.

## B-5 (minor, READ) Parser-port corpus misses the cases most likely to change upstream
`run.mjs:63-76`. There is nothing with `$VAR`/`${VAR}` (interpolation), backticks, `\'` inside single quotes, an
unterminated quote, a BOM, a lone CR, or `"a" "b"`. The port is verbatim today; all of these agree (rt.cjs).
But if firebase-tools adopted dotenv-expand or backtick quoting, the corpus would stay green while the port
diverged. **Fix:** add those lines to CORPUS (and `\r`, `\v`, trailing-backslash values to the formatLine list).

## B-6 (minor, READ) Partial-real is incoherent for the real service itself
`emulators.sh.tpl:128-183`. `EMU_REAL_SERVICES` is used only for the banner. A service committed real is still
started as an emulator, so emulated Functions get `FIREBASE_AUTH_EMULATOR_HOST` /
`FIREBASE_STORAGE_EMULATOR_HOST` while the browser uses real Auth or Storage. Admin `getUser(uid)` for a
real-signed-in user goes to the empty emulator. Function-written files land in the emulated bucket while the
browser reads the real one. **Fix:** drop committed-real services from the derived `--only` list (and say so in
the banner).

## B-7 (minor, READ) align-storage is a no-op exactly when storageBucket is unset
`emulator-project.mjs.tpl:90-91,104`. The generated environment.ts has no `storageBucket`, so in real mode
`EMU_BUCKET=''` and in offline mode `otherBucket=''`. Nothing moves, and nothing is said, contrary to "never
silently out of sight" (`emulators.sh.tpl:293-295`). Real mode also leaves the browser with no bucket
(`firebaseOptions` returns `environment.firebase` untouched), while emulated Functions use the adminSdkConfig
bucket (possibly `<id>.firebasestorage.app`). If those differ, the next align sees "both buckets hold files" and
leaves the split permanently. The `|| MOVED=""` at l.297 also swallows a corrupt metadata file. Crash mid-move is
safe only while `to` is absent from buckets.json. **Fix:** in real mode, take the bucket from the same source
the emulator uses, or refuse when it is unset. Report align failures.

## B-8 (minor, READ) The dry run discloses secret material
`emulator-secrets.cjs.tpl:544-548`. For any value longer than 8 chars it prints the first 3 and last 2 chars:
5 of 9 for a 9-char password. It also prints a 48-bit unsalted sha256 prefix, which is an offline oracle for
low-entropy secrets. That output lands in agent transcripts and CI logs. Separately, `push-secrets.sh.tpl:639`
writes every plaintext production value to `$TMPDIR` (0600, removed only by an EXIT trap, not on SIGKILL).
**Fix:** report length plus booleans (leading/trailing quote, `#`, whitespace, newline) instead of edges and a hash.
Keep the entries in a bash array or a pipe, not a temp file.

## C — composable proxy (S3 own review)

C1 MEDIUM, run+read. proxy.conf.mjs.tpl:105 — the hub route is a PREFIX (`/__bespunky/emulator-hub/`), so the app's origin relays the hub's whole control API, not just `/emulators`: `POST /_admin/export` (writes an export to any `path` in the body), `PUT /functions/{disable,enable}BackgroundTriggers`, `POST /dataconnect/clearData`. firebase-tools 15.32.1 `hub.js:66-72` answers an Origin-bearing export with 403 but does not `return` — the export still runs; the hub uses `cors({origin:true})` (ExpressBasedEmulator.js:18), so a preflighted JSON POST passes. The origin is the one port that is always forwarded to the host. Fix: relay exactly `/__bespunky/emulator-hub/emulators` (an exact key + rewrite), nothing else of the hub.

C2 LOW, run. proxy.conf.mjs.tpl:126-134 — `asObject` stringifies a webpack array entry whose `context` is a function (http-proxy-middleware allows it): the key becomes `"(p) => p.startsWith('/api')"`, a dead route, silently. A local key equal to a house key (`/emulator/`) silently replaces the house relay, and the hub probe cannot see it (it tests only the hub route). Fix: refuse (throw with the reason) a non-string context; log once, at dev-server start, every house key a local route replaces.

C3 LOW, read. proxy.conf.mjs.tpl:42 + declaration.mjs.tpl:216-219 — PORT_OFFSET/DEV_URL_QUERY/DEV_STACK_TMP are ADDED only when non-default and the env is `{...process.env, ...added}`, so a base (offset 0) stack started from inside another stack's process inherits that stack's offset/query; and a dev server started without the engine (`nx run web:dev-server`, the leaf) gets offset 0 and relays a worktree's browser to the BASE tree's suite — the very cross-tree write the header warns about; the hub probe then reports healthy. Fix: always set PORT_OFFSET (incl. `0`) and delete absent DEV_* keys; have the proxy refuse (or console-error through the probe) when no DEV_STACK_DIR is present.

Bare-Vite consumers import `viteEmulatorRoutes`, so `proxy.local.mjs` is never merged for them, and the default export uses glob keys Vite treats as literal prefixes (Firestore REST + Functions silently dead). Fix: export a merged `viteProxy` too, or document that the default export is Angular/webpack-only.
