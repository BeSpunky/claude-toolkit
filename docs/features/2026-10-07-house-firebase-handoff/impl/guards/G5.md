## BUG — 0.48.0 build-from-house-dockerfile: the "untouched seed" predicate knows one of three stubs

**Guard:** `0.48.0/build-from-house-dockerfile.ts:291` — `if (local === LOCAL_STUB_0_47)` refreshes the seeded
`post-create.local.sh`. Its comment claims the constant is the stub "as 0.47.0 (and every release before it since
the seam existed) wrote it". False: the seam shipped three stubs that differ in ONE line (line 5):

| shipped in | introduced by | line 5 |
|---|---|---|
| 0.15.0 | 2ace14b | ``# `scaffold.sh --repair`. This file is created once and never regenerated, so anything you put here`` |
| 0.16.0 – 0.38.x | 2c58e20 | ``# `scaffold.sh --sync`. This file is created once and never regenerated, so anything you put here`` |
| 0.39.0 – 0.47.x | 6a23e4e | ``# `house.sh upgrade`. This file is created once …`` ← the only one matched |

The file is SEEDED, never regenerated, so a project seeded at 0.15–0.38 still holds its original stub, byte for byte
otherwise identical (including the retired example
`# sudo apt-get update -qq && sudo apt-get install -y --no-install-recommends postgresql-client`).

**Impact.** Those projects skip the refresh, and (line 296) the file is then classed as the project's own — but the
apt example is a comment, which the report regex (`^\s*[^#\s]`) ignores, so nothing is logged either. The project
is left permanently half-migrated: its "untouched" seed keeps teaching the apt-in-post-create pattern the 0.48
rule forbids (OS packages belong in `os-packages.txt`) and names a command (`scaffold.sh --repair/--sync`) that no
longer exists. Low severity (comment/guidance only, no runtime effect), but exactly this class, and silent.

**Fixture coverage.** `tools/test-migrations/cases/0.48.0-build-from-house-dockerfile.mjs` covers only the 0.47
stub (`STUB_0_47`).

**Fix.** Recognise every shipped stub: `const SHIPPED_LOCAL_STUBS = [stub('scaffold.sh --repair'),
stub('scaffold.sh --sync'), stub('house.sh upgrade')]` (frozen literals, as now) and test
`SHIPPED_LOCAL_STUBS.includes(local)` at :291 and :296; correct the comment. Add the two older stubs as fixture
cases (refreshed, no warning). Since 0.48.0 has shipped, the repair must be a NEW rung (e.g. in 0.50.0) that
refreshes a `post-create.local.sh` still equal to the 0.15 or 0.16–0.38 stub — editing 0.48.0 alone would not
reach projects already past it.

**Repaired later?** No — no 0.50.0 migration touches `post-create.local.sh`.
