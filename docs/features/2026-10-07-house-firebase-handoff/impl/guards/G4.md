# G4 — "already current" guard audit: 0.29.0, 0.30.2, 0.33.0, 0.33.1, 0.34.0

Bug class hunted: a skip/early-return keyed on ONE marker of the new shape, fooled by a historical intermediate shape that carries the marker without the rest.

**Result: no BUG in this group.** Every guard either keys on a value that only the fully-current shape can carry (per shipped history), or keys on the *old* literal (rewrite-only-exact), which cannot be fooled by an intermediate. Two weak-but-harmless notes below.

Published `@bespunky/nx-tools` versions checked (`npm view … versions`): 0.31.x and 0.33.0 were **never published** — so the 0.31.0 voice-feature pre-release (cceff22, reverted at 8f6d093) and any 0.33.0-only shape never reached a consumer.

## Notes (weak-but-harmless, no action required)

- **0.33.0 `:103`** — the "past this rung" fact is any per-service file on disk. The one way to have those files without the rung having run is a user invoking the 0.33.x+ `firebase-emulators` generator directly ahead of migrations; the resulting disk state is byte-identical to an app that migrated and then chose the new default, so no stronger guard is possible. Fixture `0.33.1 … a replayed ladder (stamp lagging)` covers the replay this guard exists for; no 0.33.0 fixture asserts the "files present → skip" branch directly (`leaves a project alone when the services are already wired` covers the per-call-site `already` path).
- **0.30.2 / 0.29.0** read settings with strict JSON (`JSON.parse` / devkit `parseJson`); a hand-commented `.claude/settings.json` would skip silently. Not a shipped shape.

Fixture coverage: 0.33.0, 0.33.1, 0.34.0 cases exist and cover the shapes above (including import-only collisions, multi call-site, last-member removal, variants, unparseable). 0.29.0 and 0.30.2 have no fixture case.
