## BUG: 0.25.0 `retire-inline-house-sections`, the "Local servers" fingerprint misses non-Firebase 0.3–0.4 projects

**Where.** `src/migrations/0.25.0/retire-inline-house-sections.ts:141-147`, and the identical copy in `src/generators/_utils/inline-house-sections.ts`, which house-doc runs on every upgrade.

**Shape.** The section shipped in `CLAUDE.md.tmpl` from `ec7abcb` (2026-07-09) through `296d706` (0.4.0), all on main. This excerpt is from `ec7abcb`:

```md
## Local servers — never clobber a running server (non-negotiable)

**When you start a server to test a change, you MUST bind it to a random free port — never the default (`4200`{{#firebase}}, or the emulator ports …{{/firebase}}) or any container-forwarded port.** Those belong to whatever server the developer launched manually; grabbing them fails, silently attaches, or forces a disruptive restart. …
{{#firebase}}
The emulator suite is the trap: `tools/emulators.sh` **reaps existing emulator processes** on launch, … Then open the app at the printed `?portOffset=N` URL. …
{{/firebase}}
```

Both fingerprint phrases (`Then open the app at the printed \`?portOffset=N\` URL.` and `` `tools/emulators.sh` **reaps existing emulator processes** on launch``) live only inside `{{#firebase}}`. In `60bd79f` and `296d706` the first phrase is gone even from the Firebase block. A project scaffolded without Firebase in that window therefore has the heading but neither phrase. The section is classed "kept but suspicious" and left, and the frozen copy sits next to the imported `HOUSE.rules.md` version. The comment's set-cover claim was computed over raw templates. It does not hold for rendered files with the flag off.

**Fix.** Add a phrase outside the conditional to both copies of the `Local servers` entry. Its presence is verified in all four affected revisions:

```ts
'Those belong to whatever server the developer launched manually; grabbing them fails, silently attaches, or forces a disruptive restart.',
```

Re-run the set-cover check against **rendered** templates (each `{{#flag}}` both on and off), not raw ones. Add a test-generators case for `inline-house-sections` that uses a non-Firebase 0.4.0 CLAUDE.md.

**Later repair?** None. house-doc carries the same `HOUSE_SECTIONS` table (diffed: identical), so no 0.50.0 rung or generator removes it. The only consequence is a warning on every upgrade. Fixing the shared table repairs every affected project on its next upgrade without a new migration, because house-doc runs it every time.

## Note (not house-shipped): the 0.27.0 corrupted-object shape

`convert-target-comment-keys.ts:93` reports a non-string `//x` value and leaves it, so a key already exploded by older Nx (`{"0":"S","1":"p",…}`) is never repaired, despite the header's claim. Suggested fix: when every key is `"0".."n-1"` and every value is a 1-character string, rejoin the characters and then continue down the string path. The shape is project-authored (the house never wrote `//` keys), so it is weak rather than a house-intermediate bug.
