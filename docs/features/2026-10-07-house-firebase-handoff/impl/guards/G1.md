## BUG-1 — S3 (`e76c12a`): `serve` IS the dev-server and `dependsOn: ['emulators']`

Shape shipped by `e76c12a` (2026-06-02, healed by generators from `703ca41` on 2026-06-25 — but only on the one app a
sync infers):

```ts
// firebase-emulators/generator.ts @ e76c12a
const serveTarget = project.targets.serve;          // the raw @angular/build:dev-server
if (serveTarget) {
  serveTarget.continuous = true;
  serveTarget.dependsOn ??= [];
  if (!dependsOnEmulators) serveTarget.dependsOn.push('emulators');
}
project.targets.emulators = { continuous: true, executor: 'nx:run-commands',
  options: { command: `firebase emulators:start --project=${demoProject}`, cwd: '{workspaceRoot}' } };
// + emulators:auth / :firestore / :storage / :functions on the APP
```

Ladder outcome:
- 0.24.0 `:149-150`: no `dev-server`, no legacy sibling name → nothing promoted; `serve` is not run-commands → `:182`
  skipped. Its comment at `:43-44` reasons only about `serve` as the orchestrator; the S3 (and S0) case where `serve`
  is the dev-server leaf was not considered.
- 0.24.1 step 1 moves `emulators*` off the app onto `firebase` — and never retargets the app's own
  `serve.dependsOn: ['emulators']` (0.24.0 deliberately listed `emulators` in `COLLAPSED_TARGET_NAMES` to repair
  orchestrator *commands* for this exact relocation, but `dependsOn` was not swept by either rung).
- Result: `serve` = Angular dev-server with a `dependsOn` naming a target the project no longer has. Nx drops
  same-project `dependsOn` entries whose target does not exist, so `nx serve <app>` silently starts the dev-server
  **without the emulator suite**, against an environment wired to emulators. No composer, no `dev-server`; 0.35.0
  `declare-dev-processes` only handles projects whose `serve` is the house composer, so it declares nothing either.
- Repaired later? Only for the app the `web`-layer sync infers: the current serve generator
  (`generators/_utils/dev-server.ts:32` `DEV_SERVER_NAMES = ['dev-server', 'serve']`) picks the leaf up from `serve`
  and rebuilds it from options (dropping `dependsOn`). No migration through 0.50.0 touches it
  (`0.50.0/stack-owned-dev-processes` only warns about `dependsOn` on targets it made non-continuous).

Proposed guard fix (0.24.0 `reshapeServeTargets`): the "where is the dev-server" predicate must test the full current
shape — *`serve` is the composer and a `dev-server` leaf exists* — not just "a legacy sibling exists". When there is
no `dev-server` and `serve` is not run-commands and not `@bespunky/nx-tools:serve` (i.e. `serve` is a leaf), promote
`serve` → `dev-server` (stripping `dependsOn` entries naming `emulators`/`emulators:*`), and install
`{ continuous: true, executor: '@bespunky/nx-tools:serve' }` at `serve` — the same composer `:199` already writes.
Independently, 0.24.1 step 1 must retarget every `dependsOn` that names a relocated target on the source project
(string or `{ target }` form) to `firebase:<target>` (`{ projects: ['firebase'], target }`) or drop it when the
composer now owns emulator start-up, and log each rewrite. Since 0.24.x are long published, the repair belongs in a
new rung (e.g. alongside the 0.50.0 set) that detects "`serve` is a non-composer leaf with `dependsOn` naming a target
the project lacks" and re-shapes it. Fixture: an S3 app (`serve` dev-server + `dependsOn:['emulators']` + app-level
`emulators*`) run through 0.24.0 → 0.24.1.

## BUG-2 — S4 (`703ca41`): promoted `serve-no-emulators` keeps `defaultConfiguration: 'no-emulators'` (low likelihood)

Shape shipped by `703ca41` (2026-06-25 20:26; superseded by `b65399d` at 22:38 — ~2h on main):

```ts
// firebase-emulators/generator.ts @ 703ca41
noEmu.configurations = { ...keptConfigs /* development, production */,
  'no-emulators': { buildTarget: `${projectName}:build:no-emulators` } };
noEmu.defaultConfiguration = 'no-emulators';
targets.serve = { continuous: true, executor: 'nx:run-commands', options: { parallel: true,
  commands: ['nx run firebase:emulators', `nx run ${projectName}:serve-no-emulators --configuration=development`] } };
```

Ladder outcome: 0.24.0 promotes `serve-no-emulators` → `dev-server` wholesale (`:152`, "options and configurations
intact") and replaces the orchestrator with the composer — which drops the `--configuration=development` the
orchestrator used to pass. 0.24.1 deletes `build:no-emulators` and re-points `dev-server.configurations['no-emulators']
.buildTarget` to `<app>:build` (the build's *default*, i.e. production for an Nx Angular app), but leaves
`defaultConfiguration: 'no-emulators'`. From 0.35.0 the declared process runs `nx run <app>:dev-server` with no
configuration → serves the **production** environment build. Healed only for the sync-inferred app (the stack leaf is
rebuilt with the adapter's configurations).

Proposed fix: 0.24.1's retire step should treat a *configuration named `no-emulators` on any dev-server target* as
retired too (delete it; if it was `defaultConfiguration`, reset that to `development` when present), and its "already
clean" test should cover `defaultConfiguration`, not only exact `buildTarget` strings. A new rung would carry it for
already-migrated projects. Fixture: S4 app through 0.24.0 → 0.24.1, asserting the dev-server's default configuration
resolves to `development`.
