Scope: `plugins/house/engine/nx-tools/src/migrations/0.24.2/carry-legacy-firebase-prod-config.ts` (abbreviated **C** below) and `0.24.3/upgrade-emulator-environment-shape.ts` (**U**). This was a read-only audit. Line numbers refer to the worktree at `feat/house-firebase-handoff`.

## The shapes that shipped

**`firebase.config.ts`, legacy `productionFirebaseConfig` (input to C).** This shape shipped only between 2e62f9c and 4e01c0d (2026-05-29 to 05-30). It always had the same three empty fields: `projectId: '', apiKey: '', appId: ''`. The name appeared 4 times (aee834b) or 10 times (513ef99, 4e01c0d) in the file. 6106999 retired it.

**`environment.prod.ts` placeholders (written by C).** The placeholders were always `'{{x}}'` or `''` (blankCredentials). `authDomain` did not exist in 6106999 or 5d61983, and was added in 0d09453.

**`environment.interface.ts` `emulators` member (input to U).** Since 6b56f49 (nx-tools 0.1.0) this file is **write-if-absent** (`adapters/angular/firebase-client.ts:45`), so every shape below is still out there in projects:

## BUG: 0.24.3 interface "already current" guard (U:444)

```ts
const members = topLevelMembers(body);
if (members.length > 0 && members.every((entry) => declaresDefault(entry.value))) return undefined;
```

**What fools it.** These are historical shapes, verbatim. Both were write-if-absent, so they survive in projects.

- **S2**: 907329b (nx-tools 0.7.1), the same as eddc392 (0.7.0). Path: `plugins/project-starter/skills/new-project/assets/nx-tools/src/generators/firebase-emulators/environment.interface.ts.tpl`:
  ```ts
  emulators?: {
    auth?: { url: string; default: boolean };
    firestore?: { host: string; port: number; default: boolean };
    storage?: { host: string; port: number; default: boolean };
    // `proxied` (functions only): reach the emulator through the dev-server's OWN origin (its
    // proxy.conf.mjs relays callables, offset-shifted) instead of dialing host:port directly — dodges a
    // squatted/forwarded :5001 on the host and stays correct under worktree port offsets. Omitted → direct.
    functions?: { host: string; port: number; default: boolean; proxied?: boolean };
  };
  ```
- **S1**: 703ca41, 6b56f49, 60bd79f, 46d6436 (nx-tools 0.1.0–0.6.0):
  ```ts
  emulators?: {
    auth?: { url: string; default: boolean };
    firestore?: { host: string; port: number; default: boolean };
    storage?: { host: string; port: number; default: boolean };
    functions?: { host: string; port: number; default: boolean };
  };
  ```

**Impact.** U's own header promises that "opting in later is one word". On S1 and S2 that word is a compile error. This is the our-journey report: the user hand-added `proxied?: boolean` to auth to get past it. The fixture's `JOURNEY_INTERFACE` is S1 (there is no `proxied` on functions) even though its comment calls it "the 0.7.1 repair's shape". The real 0.7.1 template is S2.

**Proposed guard fix.** Compare against the canonical member set, not a single marker. The member counts as current only if **every member's normalized type equals the canonical text for its service**, where the canonical text is `{ url: string; default: boolean; proxied?: boolean }` for auth and so on, compared with whitespace and separators collapsed. Equivalently, require `default:` on every member **and** `proxied?:` on `auth` and `functions` when present. Any other `default`-carrying member set falls through to the existing replace path, which is safe here because the unknown-key abort at U:449 still protects project additions. Add fixture `historicalShapes` for S1 and S2 to the 0.24.3 case.

Because 0.50.0 retires `proxied`, the "canonical" for a 0.24.3 run made today is effectively moot. If U is fixed, it is purely for consistency in the ladder.

**0.50.0 evaluation (`route-emulators-through-origin.ts`).** The damage is **dissolved, so no repair rung is needed.**

- `planFile` walks each `<service>: {` member on its own and removes a `proxied` member wherever one exists. It never requires `proxied` on any member, so partial or absent `proxied` is fine:
  - S1 with no `proxied` → `undefined` (left byte-for-byte; covered by the fixture case "a project 0.24.3 migrated").
  - S2 → the functions member and its "// `proxied` (functions only)" paragraph are removed (the STOCK_INTERFACE case covers that paragraph).
  - S1 plus a hand-added auth `proxied?` (the journey case) → it converges to never-opted-in (fixture with `historicalShapes`).
  - A value file holding `proxied: true` against an S1/S2 interface (the broken state) → the `proxied` member is removed and the project compiles again.
- After 0.50.0, S1 and S2 are structurally identical to the current template's `emulators` member (url/host/port/default only). U's rewrite added nothing else the code depends on; only the comments differ, and those are seeded and project-owned.
- No rung between 0.24.3 and 0.50.0 reads `proxied` (`grep` finds it only in 0.24.3 and 0.50.0).
- Every ladder that runs 0.24.3 now also runs 0.50.0 (the payload is 0.50.0), so no project can stop in between.

Minor fixture gap: there is no literal S2 interface case (functions-only `proxied?` with auth bare). The mechanics are covered by STOCK_INTERFACE's functions member and paragraph, so adding one is optional.
