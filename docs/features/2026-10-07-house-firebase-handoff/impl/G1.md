## The decision, as built

**Liveness is a kernel lock, and nothing else.** A stack's claimer creates a fresh `.bespunky/run/locks/<id>.lock`,
takes a SHARED `flock(2)` on it, and holds the descriptor for life. The record names that lock. Everything that must
keep the stack alive past the claimer also holds it:
- the engine hands it to every process it spawns as fd 3;
- `emulators.sh` joins via `DEV_STACK_LOCK` (or takes its own when run directly), and its detached keeper inherits it.

"Is it alive?" is a non-blocking EXCLUSIVE try. The kernel frees the lock when the last holder exits, however it
exits. The claim mutex is an exclusive flock on the main tree's `claim.lock`. A prune happens only under that mutex,
and only for a record whose lock is free.

Deleted outright:
- takeover by rename;
- the boot id + PID-namespace staleness;
- `heartbeat()` and `STALE_MS`, with the keeper's `touch` heartbeat and the record's mtime;
- the unlocked prune in every reader;
- `claimerAlive`'s command-line check;
- the 60 s foreign rule.

A live record of ANOTHER container sharing the workspace (lock held, `machine` differs) refuses every claim and names
that stack. It is not modelled.

**Primitive choice.** `flock(1)` from util-linux, handed the descriptor as fd 3. The lock belongs to the open file
description, which the Node process keeps, so it outlives the short `flock` process. Checked:
- Node has no `flock` of its own.
- Every house image is Debian, where util-linux is essential. This container has `/usr/bin/flock` 2.41.5.
- Node marks inherited descriptors close-on-exec for what IT spawns. So a daemon an `nx` child starts never inherits
  the lock: a stack can't be held forever by a stray Nx daemon.
- An abstract unix socket was rejected. It lives per network namespace, so two containers could not see each other,
  and a detached keeper could not inherit it.

**Code, measured** (stacks.mjs code lines without comments: 344 → 430):
- The liveness machinery shrank. The old claim lock, heartbeat, record state, readStacks and removeRecord were 107
  code lines, plus the staleness constants, `bootOf` and `claimerAlive`. The new lock primitives, record state,
  records, removeRecord and readStacks are 93.
- The file grew for three things the review asked for:
  - S3-20's private TMPDIR, checked and swept: 44 lines;
  - `lockHolders`, the kernel's list of a stack's members, which `dev stop` ends on an ORPHANED stack: 34 lines;
  - in dev.mjs, the `with` command (S3-5).

**S3-17 (gitignore part) — HOLDS.** firebase-tools 15.32.1 `lib/emulator/hubExport.js:24` stages every export in
`fs.mkdtempSync(\`firebase-export-${ms}\`)` (relative → the cwd, the workspace root) and `rmSync`s the old data dir

`/firebase-export-*` block under its own marker. Its four .gitignore blocks became one marker→block table (same
`includes(marker)` test as before, so no earlier block can be re-appended). **Nothing to migrate**, deliberately: the
blocks are not appended once — each missing marker is asserted on every run (the secrets blocks reached 0.49
projects the same way), and the workspace step is not one UPGRADE_PARTIAL skips. Generator case added: a 0.49
`.gitignore` gains the line once, every marker exactly once (harness idempotence re-run). Commit `30a81488`.

**S3-18 — HOLDS.** The rung's first line was `if (!tree.exists(REAPER)) return;`, and it scanned only
`getProjects` targets + root `package.json` scripts. Reproduced: the new fixture cases run against the old rung —
"reaper already gone, caller left" and "callers in nested package.json / workflow / .vscode task / shell script / doc"
