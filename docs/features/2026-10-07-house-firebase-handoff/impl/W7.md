## Decision — where the seeded apphosting*.yaml live: STAY AT THE ROOT
Reasons: (1) it IS read — the builder walks up from the Root Directory (V4); (2) one home next to `firebase.json`, shared by every
backend, is the simplest correct default for the house's single-client-app shape; (3) moving it means a migration over user-edited
files whose only payoff is relocation (PLAN Corrections C1 already ruled it out); (4) the multi-backend case is a documented step
(per-app files) rather than the default. What changed instead: the generator seeds into the directory App Hosting ALREADY reads for the
client app (`apphosting-config.ts` `effectiveAppHostingDir`, else root) — so an upgrade never re-seeds a root file once the project
moved its own into the app (that would have created a second home), and every run warns on a shadow (`shadowedAppHostingConfigs`).
