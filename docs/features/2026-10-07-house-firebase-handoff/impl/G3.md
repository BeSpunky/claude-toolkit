| S3-10 | fixed — worse than reported | firebase-tools 15.32.1 `lib/emulator/hub.js` `PATH_EXPORT` handler: `res.status(403).json(…)` with no `return`, then the export runs (same for `dataconnect/clearData`). Reproduced on a real bare Vite with the OLD template and a real suite: `POST /__bespunky/emulator-hub/_admin/export` with an `Origin` header → 403, yet `exports/old-leak/auth_export/accounts.json` was written. Then the handler's own `res.status(200)` throws "Cannot set headers after they are sent" and **the whole emulator suite exits** (`emu-crash.log`) — so it is also a one-request kill switch. Fix: the hub route is now EXACT in every dialect — `/__bespunky/emulator-hub/@(emulators)` (an extglob: picomatch, micromatch, is-glob and tinyglobby all read it as a glob, so it is not a prefix; checked in `globtest.cjs`) and `^/__bespunky/emulator-hub/emulators$` for a bare Vite. Tests: every hub control path (and `/emulators/x`, `/emulatorsx`, the bare prefix) is NOT relayed, in both dialects and in `viteProxy`; they fail on the old template (14 failures). |
| S3-15 | fixed | Reproduced by reading `asObject`: a function `context` became a key equal to its source text (a dead route); a missing one became `"undefined"`. Angular's own Vite loader silently DROPS a non-array context too. Root cause: proxy.local.mjs had no contract that every engine reads alike. Now it has one: **each key a plain path prefix**. A function or missing context, a glob, a `^` regex or a relative key is refused at dev-server start with the reason (a glob is a prefix to Vite, a `^` key a literal to webpack-dev-server, a function no path at all). A local key equal to a house key still replaces it (the documented override) and is now said once at start, naming exactly the replaced routes. Note: the caller's "Functions routes" wording was read as the routes derived from a function `context` — that is what S3-15 describes; the Cloud Functions routes themselves were untouched. |
| S3-21 | fixed | Reproduced on a real bare Vite (old template, `proxy: viteEmulatorRoutes`): `/api/users` served the app's HTML. New export **`viteProxy`** = house Vite routes + proxy.local.mjs, with object `pathRewrite` turned into `rewrite` exactly as Angular's Vite dev server does it. Because of the plain-prefix contract the same proxy.local.mjs now means the same thing to Angular's Vite, webpack-dev-server and a bare Vite. The upgrade's "unconfigurable dev server" advice, HOUSE.md and the seeded proxy.local.mjs header name `server: { proxy: viteProxy }`. `emulatorRoutes` / `viteEmulatorRoutes` stay (house-only tables for a config of one's own). |
