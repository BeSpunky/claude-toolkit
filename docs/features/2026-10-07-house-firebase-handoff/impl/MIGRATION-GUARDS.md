# Migration guards — "already current" audit

The class (INBOUND-HANDOFF-2): a rung's skip / "already migrated" predicate keys on ONE marker of the new shape,
and a shape an earlier release shipped carries that marker without the rest — so the rung skips it and the project
stays half-migrated for good. Idempotence tests cannot see it: they re-run a rung on its own output, never on
shapes other releases wrote. Every guard of every rung (0.24.0 → 0.50.0: 42 rungs, plus the two this audit added) was checked against the
shapes that actually shipped (enumerated from git — templates, generators, earlier rungs), by seven read-only
auditors; their full notes, with shape excerpts and shas, are in `guards/G1.md` … `guards/G7.md`.

**118 guard rows; verdicts: BUG in 9 rows** (six distinct defects, below), the rest sound or weak-but-harmless
with the reason stated per row.

Found in passing (not this class, same rung, fixed in this release): `route-emulators-through-origin` removed
`proxied` but relied on the per-app generator to replace the 0.49 client glue that reads it — an UPGRADE_PARTIAL
run skips that generator, so auth and callables would silently dial :9099/:5001 again. The glue is now one seam
(`writeFirebaseClientGlue`) the adapter and the rung both call.

## Left, with reasons

- **Weak-but-harmless rows** are left as they are; each row says why (the shape is hand-made only, the rung reports
  rather than skips silently, or a later step regenerates the file). Notably: 0.27.0 `convert-target-comment-keys`
  leaves an Nx-exploded `//` key (`{"0":"S",…}`) — warned, project-authored, not a house shape; 0.24.0
  `stamp-devcontainer-ownership` keeps a `owned: false` written by one pre-0.24 sync — a documented trade-off 0.24.4
  reports; `pin-floating-dependencies` skips a hand-pinned but incoherent firebase/@angular/fire pair (not a house
  shape); `stack-owned-dev-processes` keys the suite on the project NAME `firebase` (the engine hard-codes
  `firebase:emulators`, so a renamed suite project is already outside the supported shape).
- **0.33.0 "any per-service file → skip"** cannot be told apart, on disk, from a correctly migrated app (the only
  fooling path is running the generator by hand before the migration) — no guard can do better.

## The mechanism that keeps the class out

`tools/test-migrations` cases may declare `historicalShapes` (inputs as earlier releases shipped them, sha named);
the harness asserts each converges byte-for-byte to the canonical input's result, or carries a declared
`diverges` reason — and a stale reason fails. CLAUDE.md's "Every migration gets a fixture case" now requires it of
any rung that skips "already migrated" input.
