## The firewall: one rule instance (S2-1, S2-2)

The obstacle FG named is real — ESLint replaces a rule's options wholesale per block — and is removed by HOISTING,
not by a second instance. The workspace's own options move verbatim into `const moduleBoundaryOptions`, and every
block that configures `@nx/enforce-module-boundaries` builds its entry with
`moduleBoundaries(platform) => [severity, { ...moduleBoundaryOptions, depConstraints: [...own, ...platform] }]`:

| block | entry |
| --- | --- |
| coverage (FIRST element, every extension Nx lints, so `.mts`/`.cjs` are judged even where the project's block lists fewer) | `moduleBoundaries(platformConstraints)` |
| the project's own block (its entry replaced in place) | `moduleBoundaries(platformConstraints)` |
| SSR server files | the web constraint relaxed |
| tests, tool configs | `moduleBoundaries([{ sourceTag: '*', onlyDependOnLibsWithTags: ['*'] }])` — not judged |

**Untagged projects stay fail-closed** by removing Nx's stock catch-all `{ sourceTag: '*', onlyDependOnLibsWithTags:
['*'] }` from the hoisted options (reported): it forbids nothing; its only effect is that every project matches a
constraint, which is what exempted untagged projects from "A project without tags matching at least one constraint…".

**The one thing a single instance cannot express**, stated in `firewall.ts`: Nx selects a constraint by tags a project
HAS, never by one it lacks (`hasTag`: `*`, `/regex/` and globs all test existing tags). A project with no platform tag
but another tag one of the workspace's OWN constraints matches (`scope:billing`) is therefore not reported as
platform-less. Its importers still fail (tagged projects may depend only on platform-tagged ones) and the classifier
reports it. Minimal alternative, if that ever matters: none needed in the rule — the platform generator's/sync's
report is the place. A non-stock `sourceTag: '*'` constraint is kept and reported for the same reason.

Refused (config untouched, reason + snippet printed): the rule configured in more than one place, options given as an
expression, an existing `moduleBoundaryOptions`/`moduleBoundaries` name. A config that configures the rule nowhere
gets the coverage block with `plugins: { '@nx': nx }` (same module object as flat/base: verified, no redefinition).
No namespace is registered any more, so S2-2 cannot occur.

Real ESLint (`g4/lintws`, configs rendered by the payload's own writers — insert on a stock config, upgrade of the
0.49 fixture): the same 5 platform errors as FG, each once; `allow` honoured (relative import clean; without it one
error); `ignoredCircularDependencies` honoured (2 cycle errors → 0); an untagged project's spec importing a lib clean;
SSR `server.ts`/`server/**`, `*.spec.ts`, `vite.config.mts` clean; a `platform` plugin of the project's own untouched.

The unreleased rung `close-the-platform-firewall` is reshaped (not stacked): fixture cases added for the hoisted
exemptions (`allow`, `ignoredCircularDependencies`, `checkDynamicDependenciesExceptions`), a kept non-stock catch-all,
an existing `platform` plugin, and the two-entries refusal.

## platform-sync (S2-7) — decided: a GLOBAL sync generator

`sync.globalGenerators`, never `targetDefaults.<lint>.syncGenerators`. Global generators run on `nx sync` /
`nx sync:check` only, never before a task, so no non-interactive `lint`/`deploy` is stopped by a label (verified in
`g4/syncws`: lint runs; `sync:check` reports and exits 1; `nx sync` applies). Enforcement stays lint's (the firewall
fails an untagged project's imports and every import of one); the generator is the one-command fix, and the guidance
comment in eslint.config.mjs and HOUSE.md now name `nx sync`. The CI claim is dropped, not made true: gating the
deploy workflow on `sync:check` would also gate it on every other sync generator, for a convenience. Not adding a
general HOUSE.md "out of sync" line: the house no longer registers any task sync generator.
