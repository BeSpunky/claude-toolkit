- **S3-4 fixed (decision: refuse, not reinterpret).** One rule in `emulator-secrets.cjs` (`ambiguities`): a value is
  accepted only when Firebase's reading IS its text — bare when it can be; quoted only when it must be (a `#`, edge
  whitespace, several lines, an edge quote), and then literally. Refused, by key, with the shape to write (values never
  printed — the shape elides the value, e.g. `DB_PASS='<value>'`): unquoted `#`, a `# comment` on the value line, quotes
  Firebase strips, decoded escapes (offers both readings), a stray quote, an escaped quote inside quotes, `export`.
  Reading of the decision: "surrounding quotes" are refused when the value does not need them; needed quotes are the
  only way to write such a value, so they are accepted when literal. Same rule on the emulator side: a sandbox-mode
  `.secret.sandbox.local` with an ambiguous value refuses the launch (exit 2). No old behaviour kept.
  Tests: push-secrets.test.sh (`p@ss#w0rd`, quoted `#`, `export`, literal multi-line pushed with newlines, escaped `\n`
  refused, …), emulator-secrets.test.sh.
