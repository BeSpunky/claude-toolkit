# W4 — A3: the browser reaches every emulator through the app's own origin

Branch `feat/house-firebase-handoff--w4`. Payload 0.50.0.

## Design
- **Where an emulator is reached from is a property of the caller, not the service.** `firebase.config.ts` (owned)
  exports one resolver, `emulatorEndpoint(service)` → `{ host, port, origin }`: in the browser the page's own
  origin; on a server (SSR) the container address from `environment.ts` + `PORT_OFFSET` from `process.env` (the dev
  engine exports it to every process of a shifted stack). The four `firebase-*.config.ts` just connect to it.
  Retired: `proxied` (env + interface), `emulatorFor`, `portOffset`, `offsetUrl`, `resolvePortOffset`, the
  dev fragment's `?portOffset=${OFFSET}` URL switch. No direct-dial option (user: no compat shims).
- **https** — the SDK's `connect*Emulator` forces http, so an https page throws at bootstrap with the reason and the
  two ways out (drop `ssl`, or `?emulate=none`). The migration also reports `ssl: true` dev-server/serve targets.
- **proxy.conf.mjs** relays Auth (4 prefixes), Firestore (`/google.firestore.v1.Firestore`,
  `/v1/projects/<pid>/databases`), Storage (`/v0/b`), Functions (`/<pid>`). Storage: instead of `changeOrigin:false`
  (V8's proposal) the relay rewrites `x-goog-upload-url` to a path — `changeOrigin:false` would still break behind
  the worktree-domains proxy, which rewrites Host to `127.0.0.1:<port>`. Hooked for Vite (`configure`) and
  webpack-dev-server (`onProxyRes`).
- **Forwards** — the Emulator UI's page dials every emulator (and the logging port, for its Logs tab — verified in
  the ui-v1.15.0 bundle: `//${hostAndPort}` everywhere, `ws://` to logging). So the emulator forwards stay, now FOR
  THE UI: logging (4500) added; with the UI disabled, no emulator port is forwarded. The app needs only its port.

## Proven (real run, scratch `w4/proof/RESULTS.md`)
Headless Chromium, firebase-tools 15.32.1 emulators, Angular's own `loadProxyConfiguration` (@angular/build 22.2.2)
into its bundled Vite 8.3.0, the template unchanged: Auth sign-in + token refresh; Firestore set/get/onSnapshot over
WebChannel + query; REST `runQuery` via curl; Storage 2.1 MB resumable upload (5 chunks) + download byte-identical,
upload URL received origin-relative; all of it again behind a Host-rewriting front proxy (worktree-domains shape);
`PORT_OFFSET=1000` routed to the shifted suite while the base one ran. NOT run: the Functions route, the
`/emulator` + `/www.googleapis.com` prefixes (unchanged from 0.49), SSR (house scaffolds none), webpack dev server.
