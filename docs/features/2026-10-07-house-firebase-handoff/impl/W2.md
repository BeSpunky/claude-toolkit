# W2 — Nothing run locally can reach production (A2, D4, E1)

Branch `feat/house-firebase-handoff--w2`. Payload version set to 0.50.0 (shared with the other units).

## What changed, and why this shape

**Emulator secrets (A2) — `emulators.sh.tpl`, FUNCTIONS SECRETS section.**
- The script now WRITES `dist/<functions>/.secret.local` itself on every launch. Default mode **inert**: one
  `EMULATOR_INERT_<KEY>` line per declared key. "Declared" = keys of `.secret.local.example` ∪ keys (names only) of
  the production `.secret.local` ∪ keys of the sandbox file ∪ every literal `defineSecret("KEY")` found in the built
  bundle (esbuild's `(0, x.defineSecret)("KEY")` shape included). Why a union and not one source: the example is the
  committed declaration but drifts; the bundle scan catches undocumented secrets (and the banner tells the developer
  to document them); neither catches a dynamically-named secret — hence layer 2.
- **Layer 2, the sink:** `CLOUD_SECRET_MANAGER_URL=https://secret-manager.disabled-for-emulators.invalid` is exported
  for the emulator process. firebase-tools reads it as the Secret Manager origin (`lib/api.js secretManagerOrigin` via
  `utils.envOverride`). `.invalid` is RFC 2606-reserved, so DNS never resolves it and no bearer token is ever sent
  anywhere. Covers dynamic names and the mid-session rebuild gap (`deleteOutputPath` wipes the placed file).
  Undocumented upstream knob, like `NX_IGNORE_UNSUPPORTED_TS_SETUP` — if firebase-tools renames it, layer 1 still holds.
- **Sandbox opt-in:** `<functions>/.secret.sandbox.local` (gitignored, new gitignore block with its own marker).
  Creating it is the opt-in; `EMULATOR_SECRETS=inert|sandbox` overrides per run (`sandbox` without the file exits 2).
  A sandbox value identical to the production one is REFUSED (placeholder written instead, banner says so).
- **No cross-tree borrowing of secrets** — the MAIN_WORKTREE cascade for `.secret.local` is gone (seeds still borrow).
- **Banner** names the mode, the live/inert/refused keys, undocumented bundle secrets, the sink, and `.env.local`
  overrides. Printed only when functions are part of the run.

**Params / `.env.local`.** Instead of copying `.env.local` into dist (Nx skips gitignored assets, and it would land in
the cache/deploy bundle), `firebase.json` → `functions[0].configDir = <functions root>`: the emulator and deploy read
`.env`, `.env.<projectId>` and the emulator-only `.env.local` in place. The build's `.env` asset is removed (it is now
redundant — two copies would be two sources). Recommended: COMMIT `.env.local` so every tree's emulator aims
uncredentialed calls (webhooks, chat ids) at test targets. Both `firebase.json.functions` and the build target are
generator-owned → no migration.

**Seeding (D4 + A2(d)).** The applier moved to generator-owned `tools/seed/apply.mjs` (`seed-apply.mjs.tpl`); world.mjs
is data only and imports `ref`/`at`. apply.mjs refuses without both `*_EMULATOR_HOST` vars, with a message naming the
three legitimate paths. Banner handles zero accounts and a world without `accounts`/`docs`. `writeSeedTooling()` is
exported from the generator so the migration leaves a bare `nx migrate` runnable.

**E1.** `warnUnresolvedProjectTemplates()` in the generator warns on every upgrade while `firebase.json` contains
`undefined.firebaseapp.com`; HOUSE.md says `firebase use --add` before any `firebase init`. Not repaired (unknowable).
