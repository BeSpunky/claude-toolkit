## Claim 4 — PARTLY CONFIRMED
The *generator* pins from one source (`generators/_utils/playwright.ts`, used by `generators/playwright/generator.ts`, `shared-browser`, `layers/js.ts`, `layers/web.ts`). The *migration* deliberately does NOT import it: it freezes `HOUSE_VERSION = '1.63.0'` and pins to the version resolved in `node_modules`, touching only the literal `latest`. So the precedent is "single live source for generators + frozen copy in the migration".

## Claim 5 — CONFIRMED in substance
Pin-to-installed (the playwright precedent) would freeze the incoherent pair: the root installed firebase is 12.x while @angular/fire 20 carries its own 11.x. Pinning root `firebase` to the range the installed `@angular/fire` declares (`node_modules/@angular/fire/package.json` → `dependencies.firebase`) is the coherent choice.

## Upgrade vs creation
Not creation-only. `layers/firebase.ts` runs `firebase-emulators --project=<app>` as a per-app step on every upgrade/add-layer where the layer is detected and the app is attachable; that composes `firebase-client` (firebase-emulators/generator.ts:172-180) and reaches line 104. It adds only *missing* entries, so an existing `"latest"` is never re-pinned → it stays `latest` forever without a migration; a removed entry is re-added as `latest` on the next upgrade.

## New findings
- **Angular major mismatch.** `npm view @angular/core dist-tags.latest` → `22.2.1`; no stable @angular/fire supports Angular 21 or 22 (latest 20.1.0 peers `^20`). A house Angular app on current Angular gets a peer-incompatible @angular/fire with `latest`; pinning firebase alone does not fix that — @angular/fire must be chosen to match the project's installed Angular major (and firebase from that @angular/fire).
- `@angular/fire` also peers `firebase-tools ^14 || ^15`; the firebase layer installs the CLI via a devcontainer feature, not npm — unchecked here.
- navigation-core / adopt-extracted / @nx/esbuild fallback are on-demand or edge paths (navigation layer `ensurable: false`), lower blast radius than the firebase one, which runs on every upgrade.
