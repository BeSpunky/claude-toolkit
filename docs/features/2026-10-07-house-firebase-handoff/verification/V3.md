## 5. Missing local secret → real Secret Manager? — CONFIRMED (yes)
- `FT/emulator/functionsEmulator.js:1045-1086` `resolveSecretEnvs`: reads `.secret.local`
  (ENOENT silently ignored), then for every declared secret with `!secretEnvs[s.key]` calls
  `secretManager.accessSecretVersion(this.getProjectId(), s.secret, "latest")`; failures only logged.
- Consequences: (a) an **empty** value also falls through (falsy), a `PASTE_*` placeholder does not;
  (b) the emulator project is the REAL projectId whenever `environment.ts` is filled
  (`G/emulators.sh.tpl:84-92`, precedence override > environment.ts > demo-), so with ADC/firebase login
  a dev emulator silently reads **production** secrets for any key missing locally; under `demo-` it errors and
  the function runs without the value. So placeholders (or an explicit policy) are needed for every declared key.
