The sanity-reviewer of standing-skill-pane reported at 14:30 and left a shell poll running until it was killed at 22:13. User, offered the fix: *"Yes, fix it"*.

## What actually happened

From the agent's transcript, 2026-11-03:

- The rules said to dispatch with `run_in_background: false`. The Agent tool has no such parameter, so every child came back "launched" and the agent had no sanctioned way to wait. **That false instruction is the root cause**, and it was in five places.
- 14:14:27: its first watcher grepped child transcripts for a tool name, and fired at once by matching that name in the recorded prompt.
- 14:14:49: it wrote a poll over transcripts in a foreground Bash. A finished agent's last record is a tool result, so the check could never pass.
- 14:16: a reviewer finished. Its report reached the blocked parent only at 14:24:39, when the 590s timeout moved the poll to the background, and the poll kept running.
- 14:30:23: it tried to stop the poll with `pkill -f "until node .*final.js check"`. The command line read `until node $S check`, so nothing matched, and it reported. Killed by hand at 22:13.

The session missed it too: two completion notices said "stopped with background work still running" and neither was checked.

## Observed, not assumed

A probe in this session (top session, agent, child with a 45s background command):

- An agent that ends its turn with a child running is woken by notifications, with no action of its own. So is the child, when its background command finishes.
- A child waiting on its own background work does not count as running for its parent: on a second stop the parent got `[handback-send-enforce]` and had to hand back with the child's result outstanding. Filed as harness feedback.
- That child's report then reached the top session. Nothing was lost.

The first wording here forbade `Monitor` outright and said the report always wakes you. The probe corrected both.

## Not enforced by a hook, deliberately

`SubagentStop` carries `background_tasks`, which looked like a guard. It is session-wide with no owner field, so it cannot tell this agent's leftover from a sibling's work or a dev server the session means to keep. And stopping with background work is the legitimate way to wait, so a block would break the method it protects.
