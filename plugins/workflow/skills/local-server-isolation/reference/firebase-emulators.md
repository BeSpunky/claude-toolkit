# Worked example — the Firebase emulator suite

> Applies to projects wearing the `firebase` layer (their `HOUSE.md` stamp lists it in `layers=`). The generic fixed-port-backend rules live in the SKILL; this is them applied to Firebase.

In a house project the browser reaches every emulator through the app's own origin (the dev server relays it to *its* stack's suite), but the suite itself binds **fixed** ports, which a random *app* port doesn't move. Every suite **claims** its ports as a stack before it starts (the dev engine's claim, `tools/dev/dev claim` — a serve claims for its whole stack, `tools/emulators.sh` run on its own claims `firebase@<offset>`): when another stack holds them, the launch is refused naming that stack — nothing is ever killed to make room. So naively "serving to test" on the base ports fails against the user's running suite — it never takes it down, and you must not either.

- **Never start a second suite on the default ports** — it collides with the user's and is refused. If you need emulators, run your own stack on its own block (below). Never stop their suite to free the ports.
- **Skipping the suite is not reusing theirs.** `--no-emulators` (Nx face) / `--skip=emulators` (the engine) serves the app with `?emulate=none`: every Firebase service resolves to the **real** backend. That is a deliberate choice for real/staging data — never a way to borrow the running suite, and never against production.
- In a house project, **`<serve> <app>`** (`<serve>` is what HOUSE.md names: `<pm> nx serve` for an Nx-served app, else `tools/dev/dev serve`) is its own stack every time: it claims a free block for the whole declared stack (the app + the emulator suite when the app's declaration lists it, including the hub/logging ports — `--port-offset=auto` is the default) and coexists with the developer's. Open the app at the URL it prints (or the tree's `<slug>.localhost` domain, in the shared browser or a host tab): its dev server relays to the shifted suite, so the page needs no offset of its own. Prefer this over hand-rolling an offset.
- **Stopping it saves its data** (the suite exports under a detached keeper) — wait for `tools/dev/dev stop` to return; `tools/dev/dev ps` shows a stack still saving as FINISHING. It ends itself by its deadline (`EMULATORS_STOP_TIMEOUT`); `--abandon` ends it at once, losing what it has not saved.
